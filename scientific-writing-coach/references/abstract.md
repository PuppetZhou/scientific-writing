# 摘要

## 章节职责

让未读正文的人理解研究为何值得做、具体问什么、怎样回答、得到了什么或准备得到什么。不要把摘要写成方法目录。

## 优先追问

- 读者首先需要知道哪一个背景问题？
- 本研究相对于已有工作最具体的未知是什么？
- 哪一项发现或预期交付是核心，哪些属于辅助？
- 摘要中的结果和数字是否已被正文支撑？

## 可选结构模板

**已完成研究，适合渐进引入：**
背景/需求 → 具体困难与缺口 → 聚焦问题 → 回答问题的核心设计 → 主要发现与关键依据 → 有边界的意义。

**研究计划：**
背景 → 问题 → 聚焦 → 核心方案 → 判断是否成功的评价 → 预期贡献。

**结构化摘要：**
按期刊规定的 Background / Methods / Results / Conclusions 分配同一条论证链，不为保持通用模板而改动规定格式。

英文修辞骨架仅供选择，不逐句照抄：
- “Although [established capability], [specific uncertainty] remains unresolved.”
- “We tested whether [specific question] using [answer-enabling design].”
- RP使用“This project will test whether…”，不把尚未发生的结果写成“We demonstrate…”。

## 编辑要点

开头通常用一两句建立需求，再引入目标，避免空泛时代背景。若用户或期刊要求直接目的式开头，则遵从要求。正文定稿后再回写摘要。

核心方法保留到足以解释为什么能回答问题；候选模型、参数和全部敏感性分析不逐项列出。结果优先一项中心发现及其必要支持，不凑固定数字个数。

末句说明这项发现改变了什么、或计划完成后能形成什么，而不是再次复述目的。摘要必须自明；不依赖正文缩写、未解释的数据库名或“上述方法”。
